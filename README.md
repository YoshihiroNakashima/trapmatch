# TrapMatch

A local web app that reconciles camera-trap video files across storage locations (HDD, NAS and a CSV listing), season by season. The interface and this document are in Japanese.

カメラトラップ動画の保存場所（HDD、NAS、CSV の一覧）を Season 単位で照合し、食い違いを目で確かめながら「残す」「削除する」を判断するためのアプリです。

この版（第 1 版）は、保存場所のファイルと元の CSV を一切変更しません。行うのは読み取りと、作業用フォルダへの書き出しだけです。コピーや退避の実行は次の版で扱います。

## インストール

### Windows

1. [Releases のページ](https://github.com/YoshihiroNakashima/trapmatch/releases/latest) から `TrapMatch.exe` を取ってきます。
2. デスクトップなど好きな場所に置いて、ダブルクリックします。Python を入れる必要はありません。
   「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を押します。
3. 黒い窓が開き、続いてブラウザに画面が出ます。

新しい版にするときは、Releases から新しい `TrapMatch.exe` を取ってきて置き換え、起動します。設定と作業状態はホームフォルダの `TrapMatchData`（`C:\Users\<ユーザー名>\TrapMatchData`）にあり、exe を入れ替えても残ります。使うのをやめるときは、exe とこのフォルダを消します。

### macOS、Linux、または Python から動かす場合

必要なのは Python 3.8 以上だけで、追加のパッケージは要りません。

```
git clone https://github.com/YoshihiroNakashima/trapmatch.git
cd trapmatch
python3 app.py
```

Windows では、フォルダの中の `起動.bat` をダブルクリックしても起動します。

## 起動と終了

起動すると黒い窓が開き、続いてブラウザに画面が出ます。終了するときは黒い窓を閉じます。ブラウザの画面を閉じただけでは終了しません。画面を閉じてしまったときは、もう一度起動すると同じ画面が開きます。

新しい版を起動したとき、前の版が動いたままなら、新しい版がそれを終了させてから起動します（走査や書き出しの途中では終了させず、案内を出します）。0.1.4 以前の版はこの仕組みに対応していないため、その版の黒い窓は手で閉じてください。動いている版は画面左上に出ます。プログラムだけが新しくなっているときは、画面の上に起動し直しの案内が出ます。

引数を付けて起動すると、ポート（`--port 8770`）、設定と作業状態の保存先（`--data-dir フォルダ`）、ブラウザを開かない（`--no-browser`）を指定できます。

## はじめに行うこと

1. 「保存場所と設定」で、照合する保存場所を登録します。フォルダは「親フォルダ / Season / Station / 動画」の階層の親フォルダ（PRM_N に当たるフォルダ）を、CSV は Season、Station、File 列を持つファイルを指定します。
   CSV が Season ごとに分かれている場合は、場所に `{Season}` と書くと Season 名に置き換わります（例: `D:\lists\{Season}.csv`）。
2. Season を選ぶか入力して「走査」を押します。全角で入力した英数字は半角にそろえます。どの保存場所にも CSV にも動画が見つからない名前では、走査の結果を作りません。
3. 一覧に不一致の動画だけが並びます。行を選ぶと右側で再生されます。

## 画面の使い方

左側で絞り込みます。「不一致のみ」は判断が必要な動画（欠け、CSV のみ、サイズ違い、場所内の重複、サイズ 0）だけを表示します。「保存場所の組で絞る」は、その 2 つの保存場所のあいだで食い違う動画だけを表示します。状態や所在パターン、Station、ファイル名でも絞れます。

絞り込んだ一覧には、前後の動画も出ます。表示中の動画が連続しているまとまりごとに、同じ Station でその最初の一つ前と最後の一つ後にある動画を足し、状態の欄に「一つ前」「一つ後」と出します（前後に動画がなければ足しません）。前後の動画は再生して見比べるためのもので、判断とメモは変えられず、まとめての判断や本数にも入りません。出したくないときは、左側の「前後の動画も表示」を外します。

判断は右側のボタンかキーで付けます。行を移った直後は、右側の表示がその動画に切り替わるまで判断を受け付けません（見ていない動画に判断が付くのを防ぐためです）。走査中も、判断とメモは変更できません。まとめて付けるときは、一覧の上の「表示中の動画にまとめて」を使います。Shift や Ctrl を押しながらクリックすると複数の行を選べ、その場合は選んだ行が対象になります。

| キー | 動作 |
| --- | --- |
| ↑ ↓ | 前後の行へ移る |
| スペース | 再生と停止 |
| ← → | 2 秒戻る、進む |
| 1、2、4 | 再生の速度 |
| K | 残す |
| D | 削除する |
| E | 例外として残す |
| U | 未判断に戻す |

AVI（MJPEG）と MP4 はアプリの中で再生できます。それ以外の形式の AVI は、ffmpeg があれば変換しながら再生します。再生できないときは「既定のプレーヤーで開く」を使ってください。

## 書き出し

「書き出し」から、表示中の Season について 3 種類のファイルを作れます。保存先は作業用フォルダの `exports/<Season>/` です。全 Season をまとめた書き出しもあります（この節の最後）。

- 照合結果の一覧: 全動画の所在、状態、判断、メモ。
- 更新後の CSV: 行の追加（「残す」と判断した、CSV にない動画）、行の削除（「削除する」と判断した動画）、File の拡張子の更新を反映した CSV。元の CSV は書き換えず、別の名前で作ります。変更しない行は元のまま書き写します。
- 実行計画（確認用）: 判断どおりにそろえるために必要なコピーと退避の一覧。

追加する行の DateTime の取得元は、書き出しの窓の「追加する行の DateTime」で選びます。

- 動画に埋め込まれた撮影日時のみ（なければ `NA`）。これが既定です。
- 埋め込まれた撮影日時、なければファイルの更新日時。

埋め込みの日時は、AVI では IDIT、MP4 と MOV では作成日時（mvhd）から読みます。カメラによっては、動画に日時がまったく記録されていません（Browning の AVI で確認）。その場合、日時の手がかりはファイルの更新日時だけです。

ファイルの更新日時は、コピーや変換で変わることがあります。そのため書き出しの窓に、CSV に行がある動画について「ファイルの更新日時が既存の DateTime と合う本数」を表示します。これが高ければ、更新日時を使ってよいと判断できます。保存場所のあいだで更新日時が違う動画では、最も古いものを使います。動画を読めなかったとき（接続が切れているなど）は、更新日時には切り替えず `NA` にして件数を知らせます。

書式は CSV の既存の行に合わせます。既存の DateTime が分単位（秒がすべて 00）の Season では、追加する値も秒を 00 に切り捨てます。変換で作った MP4 では、埋め込みの日時が撮影日時ではなく変換した日時になっている可能性があります。「埋め込みの日時を既存の DateTime と突き合わせる」で確かめられます。

追加する行のほかの列には、列ごとの既定値が入ります。組み込みの既定値は次のとおりで、ここにない列（DateTimeCorrected、DateTimeIsOk、DateTimeChange など）は空欄になります。

| 列 | 値 |
| --- | --- |
| Season_sub_folder | Season 名（設定では `{Season}` と書く） |
| DeleteFlag | FALSE |
| Pass | TRUE |
| Star | FALSE |
| Remarks | NA |
| PassCount | 0 |
| Indep | TRUE |
| LeftCens | FALSE |
| RightCens | FALSE |
| StartTime | 999.9 |
| EndTime | 999.9 |
| Species | Add |

既定値は「保存場所と設定」の「CSV に足す行の既定値」で変えられます（1 行に 1 列、「列名=値」の形）。列名は大文字と小文字を区別せずに CSV の見出しと照らし、CSV にない列名は無視します。行ごとに違う値にしたいときは、その動画の「CSV に足す行」の欄に入力すると、既定値より優先されます。

CSV にしかない動画（登録している保存場所のどこにも動画がない行）を「残す」と判断すると、更新後の CSV でその行に印が付きます。既定の印は `csvのみ` で、CSV に Note 列があれば Note 列、なければ Remarks 列に書きます。空欄と `NA` は印に置き換え、ほかの文字が入っている行では消さずに `; csvのみ` を後ろに足します。すでに印が入っている行は変えません。「例外」と「未判断」の行には付けず、「削除する」の行は除きます。印の文字と書く列は「保存場所と設定」で変えられ、印を空にすると付けません。書き出しの窓のチェックを外せば、その回だけ付けずに書き出せます。

英数字だけの CSV は UTF-8 とみなします。そのような CSV に日本語の印や値を書くと、その部分は UTF-8 になります（日本語を含む Shift_JIS の CSV では Shift_JIS のまま書きます）。

「全 Season をまとめて書き出す」は、走査済みのすべての Season について、不一致の動画と判断を 1 つの CSV（`exports/all_seasons/照合結果_全Season_日時.csv`）にまとめます。対象は、不一致の動画と、判断またはメモのある動画です（「一致している動画も含める」を入れると、すべての動画）。列は 1 つの Season の「照合結果の一覧」と同じで、最後に走査の日時（ScannedAt）が付きます。Season ごとの本数（動画、不一致、未判断、残す、削除する、例外、状態ごとの本数）をまとめた集計（`集計_全Season_日時.csv`）も一緒に作ります。内容は、それぞれの Season を最後に走査したときの照合結果と、いまの判断です。

## データの保存先

設定と作業状態（走査の結果、判断、メモ）は、ホームフォルダの `TrapMatchData` に保存されます。アプリのフォルダを入れ替えても消えません。別の場所にしたいときは、`--data-dir <フォルダ>` を付けて起動します。

再走査しても、判断とメモは動画ごとに引き継がれます。

## この版でやらないこと

- 動画のコピー、退避、削除（判断と実行計画の書き出しまで）
- 元の CSV の書き換え（更新後の CSV を別名で書き出すまで）
- AVI から MP4 への変換
- 複数の人による同じ Season の同時作業

## 開発

`tests/` に自動試験があります。実行は `python -m pytest -q` で、pytest と Pillow のほか、試験用の動画を作るために ffmpeg が必要です。画面の通し確認は `python tests/ui_check.py 出力先`（Playwright が必要）です。

配布用の `TrapMatch.exe` は、GitHub Actions が Windows の環境で作ります（`.github/workflows/build.yml`）。`v0.2.0` のような tag を付けて上げると、試験、exe の作成、作った exe の動作確認を行い、通ったものを Releases に載せます。手元で作るときは `python packaging/build_exe.py`（PyInstaller が必要）、作ったものの確認は `python packaging/smoke_test.py dist/TrapMatch.exe` です。

変更の記録は [CHANGELOG.md](CHANGELOG.md) にあります。
